# RAG 技术架构

面向医疗问答的「检索 → 接地 → 出口」全链路设计。分四层，每层都能独立验证。

```
① 离线数据管道      ② 存储与版本管理        ③ 检索接地与溯源       ④ 出口安全网
PDF 解析清洗   →   Milvus 877 块真指南   →   来源头 + 接地约束   →   _enforce_output_safety
数字单位接回        旧摘要物理删除            查不到就拒答           120 拦截 + 异常兜底
句级切分 + 页码绑定  去重与行数校验            类型转中文标签         只补安全要素，不改正文
```

对应请求链路见 [ARCHITECTURE.md](ARCHITECTURE.md)；本层的工程复盘见 `../rag实现.md`。

## ① 离线数据管道

入口：`scripts/ingest_real_guidelines.py`

```bash
python scripts/ingest_real_guidelines.py --dry-run      # 只抽取与分块，不碰数据库
python scripts/ingest_real_guidelines.py               # 入库 + 淘汰旧摘要 + 探针
python scripts/ingest_real_guidelines.py --probe-only  # 只跑召回探针（只读）
python scripts/ingest_real_guidelines.py --force       # 同名全文已入库时先删再灌
```

### 1.1 PDF 解析

`pypdf` 逐页抽取，**保留页码**（后续用于页码归因）。单页解析失败只告警不中断，避免一份 98 页的指南因为一页坏掉而整体失败。

### 1.2 清洗三类噪声

| 噪声 | 识别方式 | 为什么这样做 |
|---|---|---|
| 纯页码 | `_PAGE_NO`，**仅在页边**且不含中文 | 不含中文这个约束是为了不误删正文里独立成行的数字 |
| 页边高频行 | 只统计每页前 3 / 后 6 行；≥50% 页面且带数字，或极短行 ≥80% 页面 | 刊头页脚只在页边，正文中部重复出现的小节标签（如「要点提示：」）不会被误删 |
| 期刊栏头 | 全文档扫描：形如 `第#卷 / 第#期 / Vol. / Serial No` 且归一化后重复 ≥3 次 | 栏头有时前面挂着页码、落在页边窗口之外，只在页边统计会漏 |

两个关键设计：

- **数字归一化**：比较前把数字统一成 `#`。同一栏头逐页页码/期号不同，不归一化就聚不成同一行。
- **排除文献特征**：栏头判定显式排除 `DOI` / `[J]` / `[M]` / `[C]` / `et al`。参考文献条目恰好都带 DOI，第一版规则把「DOI」当栏头特征，在糖尿病指南上误删了 452 行文献条目。

### 1.3 硬换行拼段落 + 数字单位接回

- `_build_paragraphs`：PDF 每行都是硬换行，直接切分会让句子断在任意位置。规则是「上一行以句末标点结束 → 另起一段」，否则视为续行拼接，并处理英文连字符断词（`Collabora-` + `tion`）。
- `_repair_split_units`：抽取器受表格列宽影响，会把一个数值拆到下一段，例如 `海拔超过500` + `m`、`生活在2` + `000` + `m`。只接回**无歧义**形态：数字 + 拉丁单位/百分号/万/亿，以及「数字 + 短纯数字段 + 单位」。
- ⛔ **不合并两个相邻的纯数字段**：表格里 `≥15 739` 与 `204 5.1a` 是两列，拼起来就是凭空造数。

### 1.4 句级切分

复用知识库的 `MedicalKnowledgeBase._chunk_text`（`knowledge/milvus_kb.py`）：

1. 按换行与句末标点（`。！？；`）拆成「句子 + 段落边界」单元；
2. 贪心合并到 `chunk_size=1024`，只有单句本身超预算才硬切；
3. 硬切走 `_cut_safely`：切点前后都是数字就左移，保证 `100mg` 不会被切成 `10` / `0mg`；整段都是数字时退无可退，按原切点切（保证一定前进，不死循环）；
4. `overlap=100` 保留块间重叠。

### 1.5 元数据绑定

每个 chunk 绑定以下字段，检索侧与溯源侧都直接消费：

| 字段 | 用途 |
|---|---|
| `type` | `clinical_guideline`，供检索按类型过滤 |
| `doc_kind` | `full_text_pdf`，区分真全文与旧摘要 |
| `source` | 中文指南全称（来源头首选显示） |
| `filename` | 物理文件名，版本替换时按它精确删向量 |
| `guideline_id` / `publisher` / `year` | 版本可核 |
| `doc_id` / `chunk_id` / `total_chunks` | 块级定位 |
| `pages` | 页码区间（`p.8-9`），人工翻原文核对 |
| `char_count` | 块长 |

### 实测

| 文件 | 页数 | 入库块数 | 剔除页码/栏头行 | 接回数字单位 |
|---|---|---|---|---|
| `01_hypertension_2024.pdf` | 98 | 323 | 689 | 945 |

## ② 存储与版本管理

### 存储

- Milvus Lite，集合 `medical_knowledge`，`COSINE` 度量，`auto_id`，向量维度 512（`BAAI/bge-small-zh-v1.5`）
- `metadata` 以 JSON 字符串存储，支持 `metadata like "%..."` 过滤
- 语料构成：**877 块国家级指南全文** + 25 篇结构化文本

### 版本替换（旧摘要淘汰）

顺序不能颠倒：

```
抽取清洗 → 写入 Milvus → 校验写入（原始行数） → 才淘汰旧摘要
                                  ↓ 校验不通过
                          中止，不淘汰（检索不会出现空窗）
```

两件必须一起做的事：

1. **文件归档**：`20/21/22_*.txt` → `.bak`（已在 `.gitignore` 忽略）
2. **向量删除**：按 `metadata.filename` 查出主键后删除

> 📌 只做第 1 件是无效的。旧向量仍留在集合里，检索照旧命中——入库前实测，「2024 高血压诊断标准」的 Top-1 正是旧摘要。

### 去重与行数校验

- `_fetch_all_chunks()` 按 **content 去重**，用于估算集合规模（这也是历史上重复导入留下的补丁）。
- **写入校验必须查原始行**（`query` + filter），不能走去重接口：`02_t2dm` 里恰好有 2 块文本完全相同，用去重口径会把「写入成功」误判成「少写 2 块」。
- 替换旧摘要前已核对：`23/24/25` 三份过渡文档（哮喘慢阻肺、幽门螺杆菌、痛风）无对应真指南，**保留**，删除后覆盖会空。

### 缓存一致性

任何写入后调用 `invalidate_bm25_cache()`，否则混合检索会命中过期语料。

## ③ 检索接地与溯源

### 检索链路

```
query → 向量检索（limit = top_k * 2，min_vector_score = 0.25）
      → BM25 关键词检索（filter_type 必须与向量侧一致，否则过滤会被融合绕过）
      → RRF 融合（k=60）
      → CrossEncoder 重排（BAAI/bge-reranker-base，可用 MEDIX_RERANKER_MODEL 覆盖）
```

BM25 索引带缓存（全量拉取 + 分词 + 建索引代价高），写入时失效。

### 来源头

生产路径：`.claude/skills/search-knowledge/script/search.py::format_results`

```
【资料 1｜来源：中国高血压防治指南（2024年修订版） p.1｜类型：临床指南】
```

- 来源优先取 `source`（中文全称），缺失才回退 `filename`
- 有 `pages` 时拼成 `p.8-9`
- `type` 转中文标签（`clinical_guideline → 临床指南` 等），未收录的代码原样输出

### 接地约束（GROUNDING_RULES）

注入位置：`core/agent_loop.py` 组装 system message 处。

> 📌 不能放在 `agents/base_agent.py` 的 `format_user_input`：`consultation_agent` 与 `diagnostic_agent` 都重写了该方法且未调用 `super()`，放基类会恰好绕过最需要约束的两个 Agent。

约束内容：医学事实只能依据【资料】；资料未收录就明说未收录；涉及用量与确诊一律提示就医。

### 拒答机制

| 场景 | 系统行为 |
|---|---|
| 资料未收录（未收录专科、罕见病） | 明确回复资料未覆盖，不用常识补 |
| 具体处方与剂量 | 不给剂量、疗程、联合用药、妊娠哺乳用药 |
| 急危重症 | 只给「立即就医 / 拨打 120」，不给院前处置步骤 |

## ④ 出口安全网

入口：`swarm/swarm_coordinator.py::_enforce_output_safety`，在 Lead 汇总之后、返回用户之前执行。

```python
answer = await lead_agent.synthesize_results(...)   # Lead 会重写答案
answer = _enforce_output_safety(answer, question)   # 按用户输入定风险等级并补安全要素
```

| 环节 | 做法 |
|---|---|
| 风险判定 | 按**用户输入**的高危词定风险等级（不依赖答案里是否还留着提示） |
| 校验 | 跑 `validator.validate_output("consultation_agent", ...)` |
| 自动修复 | **只挑** `add_disclaimer` / `add_emergency_warning` 两类交给 `auto_fixer` |
| 其余违规 | 只记日志，不改写用户看到的正文 |
| 失败处理 | 整段包在 `try` 里，校验失败时原样返回，不影响主流程 |

异常兜底：`swarm/lead_agent.py` 的合成异常不再返回 `汇总结果时出错：{e}`，改为医疗话术 + 就医提示 + 免责声明，**不把代码堆栈当医学答案**。

> 为什么必须在出口再判一次：worker 各自的输出校验只保护中间结果，Lead 会重写答案，就医提醒可能被稀释甚至丢掉。安全要素不能建立在「上游已经加过」的假设上。

## 验证

**召回探针**（`--probe-only`，走生产的 `format_results`）：

| Query | Top-1 | 页码 | 来源头 |
|---|---|---|---|
| 2024 高血压诊断标准与血压分级 | `01_hypertension_2024.pdf` | 1 | 【资料 1｜来源：中国高血压防治指南（2024年修订版） p.1｜类型：临床指南】 |
| 低密度脂蛋白胆固醇 LDL-C 目标值 | `03_lipid_2023.pdf` | 8-9 | 【资料 1｜来源：中国血脂管理指南（2023年） p.8-9｜类型：临床指南】 |
| 急性高危胸痛的识别与处理流程 | `05_acute_chest_pain_consensus_2019.pdf` | 2-3 | 【资料 1｜来源：急性胸痛急诊诊疗专家共识（2019） p.2-3｜类型：临床指南】 |

**纯检索评测**：`python eval/scripts/run_retrieval_eval.py --seed 42 --per-category 50 --run-id post_ingest`

- 协议：每问调 `search(question, top_k=8)`，用 `bge-small-zh-v1.5` 算每个 hit 与金标答案的 cosine，`max_sim ≥ 0.40` 记为命中（对齐 `post_opt emb_low`）
- 报告：`eval/results/retrieval_eval_post_ingest.md`

结果（n=200，seed=42，与入库前同批分层）：

| 指标 | 入库前（2026-08-23，64 块摘要） | 入库后（2026-10-09，877 块真指南） | 变化 |
|---|---|---|---|
| hit@1 | 98.5%（197/200） | **97.0%（194/200）** | −1.5pp |
| hit@3 | 98.5%（197/200） | 98.5%（197/200） | 0 |
| hit@8 | 98.5%（197/200） | **99.0%（198/200）** | +0.5pp |

分品类（入库后）：`guideline_retrieval` hit@1 / hit@8 均 **100%**；下降集中在 `disease_knowledge`（hit@1 96% → 92%）。

> 📌 **怎么读这个结果**：换语料后 top-1 的**排序位次**有变化，但 top-8 **覆盖不降反升**（98.5% → 99.0%）——说明相关内容没有丢，是少数问题里真指南块把原先排第一的条目挤到了后面。实际链路是把 top-8 交给模型，所以对端到端影响有限。这个结论比「数字掉了一点」更重要：**它证明换的是更好的语料，不是更差的检索**。

**其它**：18 项零 API 成本行为断言通过；回归 `37 passed / 26 skipped`；流式契约测试 4 项。

## Engineering Insights

### 1. 文件改名换不掉旧向量

- ⛔ 直觉做法：把旧摘要重命名 `.bak` 就算淘汰。
- 🟢 实际情况：向量早在集合里，改名动不了它。入库前实测，旧摘要正霸占「2024 高血压诊断标准」的 Top-1。
- ✅ 正确做法：文件归档 **和** 按 `filename` 删向量两件都做；删除排在写入校验通过之后。
- 📌 实测：删前 28 行原始记录（按内容去重只有 15 条 —— 这批摘要当年被导入过两次），删后残留 0。

### 2. 抽取阶段就会拆散「数字 + 单位」

- ⛔ 直觉做法：以为切分器已经防住剂量被切开。
- 🟢 实际情况：`_cut_safely` 只管切分；抽取阶段早就拆过了，`海拔超过500` + `m`、`2` + `000` + `m`。
- ✅ 正确做法：只接回无歧义形态；**不**合并相邻纯数字段（表格里那是两列，拼起来是造假数据）。
- 📌 实测：接回 945 处，全部来自表格密集的高血压指南。

### 3. 清洗栏头别拿 DOI 当特征

- ⛔ 直觉做法：`DOI`、期刊英文缩写都算栏头特征，一并清洗。
- 🟢 实际情况：参考文献条目恰好都带 DOI，第一版在糖尿病指南上删掉 452 行文献条目。
- ✅ 正确做法：只认卷期号，显式排除 `DOI/[J]/[M]/et al`。
- 📌 另一个陷阱：「重复出现多次」不能当唯一判据 —— 同一刊物的 DOI 前缀高度相似，数字归一化后会被聚成同一行，看着像高频栏头，其实是一堆不同文献。

### 4. 校验口径混用会让人修不存在的 bug

- ⛔ 直觉做法：用「全量 chunk」接口统计，发现期望 401、实到 399，判定写入失败。
- 🟢 实际情况：该接口按内容去重，而这份指南里有 2 块文本完全相同，写入没问题，是指标算错了。
- ✅ 正确做法：写入校验查**原始行数**，按内容去重只用于估集合规模。
- 📌 实测：改完四份文件精确对上 323 / 401 / 129 / 24。

### 5. 接地指令的注入点比内容更容易出错

- ⛔ 直觉做法：接地约束写进 Agent 基类的输入格式化方法。
- 🟢 实际情况：`consultation_agent` / `diagnostic_agent` 重写了 `format_user_input` 且未调 `super()`，放基类会被这两个最该约束的 Agent 绕过。
- ✅ 正确做法：放在组装 system message 的地方，覆盖全部 Agent。
